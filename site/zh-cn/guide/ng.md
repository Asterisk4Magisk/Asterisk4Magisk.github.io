# AsteriskNG

AsteriskNG 是基于 **Xray** 核心的客户端，以「节点列表」为中心：每个节点都可以单独编辑、分享，再通过订阅分组、策略组、链式代理与路由规则组合使用。

底部导航共四页：**代理**、**路由**、**应用**（分应用代理，见 [通用功能](./common#per-app-proxy)）和 **设置**。

## 订阅分组

订阅在 **设置 → 常规 → 分组管理** 中维护。每个分组可以是：

- **订阅分组**：填写订阅地址，应用会定期拉取节点；
- **手动节点分组**：订阅地址留空，用来存放手动添加的节点。

| 字段 | 说明 |
| --- | --- |
| **分组名称** | 留空则首次同步后自动命名 |
| **订阅地址** | 手动分组可留空。使用 HTTP 明文地址时会弹出警告 |
| **自动更新间隔（小时）** | 不少于 0.25 小时 |
| **User-Agent** | 可选 v2rayNG、Clash Meta 或自定义；部分服务商据此返回不同格式 |
| **HWID** | 向支持设备数量限制的服务商上报设备标识 |
| **Mihomo Age 私钥** | 用于解密使用 Age 加密的订阅 |
| **使用代理更新** | 通过本地代理请求订阅地址，适合订阅地址本身被阻断的情况 |

在 **代理** 页的更多菜单中点击 **更新订阅**，会更新全部订阅分组。多分组时，可在设置中开启 **启用“全部”分组**，在节点列表顶部显示一个汇总分组。

## 节点列表

**代理** 页显示当前分组的节点。点击节点即可选中；选中后点击 **启动代理**，运行中再次点击则 **停止代理**。

页面的更多菜单提供：

- **握手延迟测试**：测量与服务器的握手延迟，不经过完整代理链路。
- **测试真连接**：通过节点发起真实请求，更能反映实际可用性。
- **布局**（单列 / 双列 / 多列）与 **排序**（默认 / 延迟 / 名称）。
- **搜索节点**、**复制所有节点URL**。
- **删除重复代理节点**、**删除无效代理节点**、**删除全部代理节点**。
- **服务重启**：修改配置后让运行中的服务立即应用。

节点卡片上的按钮 / 菜单可 **编辑**、**分享** 或删除节点。分享方式有 **分享 URL**、**二维码** 和 **完整 JSON**。

## 添加节点

点击添加按钮可选择 **扫描二维码**、**从剪贴板导入**、**从文件导入**，或 **手动输入** 以下类型：

| 类型 | 说明 |
| --- | --- |
| VLESS / VMess / Trojan / Shadowsocks | 常见代理协议，支持 RAW、XHTTP、WebSocket、gRPC、HTTPUpgrade、mKCP 等传输方式与 TLS / REALITY |
| Socks / HTTP | 上游 SOCKS5 / HTTP 代理 |
| Hysteria2 | 支持带宽设置、端口跳跃与 salamander 混淆 |
| WireGuard | 填写密钥、本地地址、MTU、Reserved 等 |
| MASQUE | 基于 HTTP 的 IP 代理，可选 WARP 设置 |
| Custom | 直接粘贴 Xray JSON（完整配置或仅出站）；可选 **覆写入站设置和 DNS 设置**，改用 AsteriskNG 提供的入站与 DNS。覆写规则见 [Xray 配置 · Custom 节点](./core-xray#custom) |
| 策略组 | 见下文 |
| 链式代理 | 见下文 |

编辑器会逐项校验字段。若部分项目未通过完整校验，可选择 **返回修改** 或 **继续保存**（配置可能无法正常使用）。

### 策略组

策略组按规则从一组节点中自动选择出站：

- **策略组类型**：**最低延迟**、**最低负载**、**随机选择**、**轮询**。
- **订阅分组**：节点来源，可选某个分组或 **全部分组**。
- **别名正则过滤**：用正则表达式按节点名称筛选，例如 `香港|HK`。

::: details 核心实现
策略组会生成 Xray `routing.balancers` 中的负载均衡器，类型对应 `leastPing`、`leastLoad`、`random`、`roundRobin`。「最低延迟」依赖 `observatory` 定期测速，「最低负载」依赖 `burstObservatory` 综合延迟与稳定性。详见 [Xray 配置 · 节点如何变成出站](./core-xray#outbounds)。
:::

### 链式代理

链式代理让流量依次经过多个节点（**代理链成员**，至少两个），例如「中转节点 → 落地节点」。列表中会显示链的跳数。

::: details 核心实现
每个成员生成一个出站，后一跳的 `streamSettings.sockopt.dialerProxy` 指向前一跳，即后一跳的连接经由前一跳建立。
:::

## 路由规则

**路由** 页管理 Xray 路由规则，决定每条连接走 **代理**、**直连** 还是 **阻止**。

每条规则可组合以下匹配条件：

| 条件 | 示例 |
| --- | --- |
| **域名规则** | `domain:example.com`、`geosite:cn` |
| **IP规则** | `1.1.1.1`、`10.0.0.0/8`、`geoip:cn` |
| **端口** | `443`、`1000-2000` |
| **网络类型** | `tcp`、`udp` |
| **协议类型** | 如 `http`、`tls`、`bittorrent`（依赖嗅探） |
| **进程规则** | 按应用进程匹配 |

**出站代理标签** 除了代理 / 直连 / 阻止，也可以指定某个节点或策略组。

- 标题栏右上角的菜单用于设置 **默认出站代理标签**（没有规则命中时使用），当前值显示在标题下方。
- 列表顶部的 **域名策略** 用于选择 **域名解析策略**。
- 规则按列表顺序自上而下匹配，可拖动调整顺序，也可单独启用 / 停用某条规则。

规则可通过 **从剪贴板导入** / **导出到剪贴板** 批量迁移，导入时可选择合并或替换。

::: tip geosite / geoip
`geosite:` 与 `geoip:` 规则依赖资源文件，可在 **设置 → 常规 → 资源管理** 中切换 Loyalsoldier、V2Fly、Chocolate4U、RunetFreedom 等规则来源。
:::

想了解规则如何写入 Xray 配置、支持哪些域名写法，见 [Xray 配置 · 路由规则写法](./core-xray#routing-rules)。

## 核心设置

### DNS 设置

| 设置项 | 说明 |
| --- | --- |
| **启用 DNS 劫持** | 由核心处理 DNS 请求 |
| **FakeDNS** 与 **FakeDNS 地址池** | 为域名分配虚拟 IP，加快连接并让路由按域名生效 |
| **直连 DNS** 与 **直连 DNS 适用域名** | 指定哪些域名使用直连 DNS 解析 |
| **使用直连 DNS 解析节点** | 让代理节点自身的域名走直连 DNS |
| **代理 DNS** | 经由代理查询的 DNS 服务器 |
| **DNS hosts** | 静态解析，格式：`域名:地址1,地址2` |
| **解析节点域名** | 将代理节点的 IP 写入 DNS hosts |

### 嗅探、Mux 与 Fragment

- **Sniffing**：识别 HTTP / TLS 等目标域名辅助路由；开启 **routeOnly** 时嗅探到的域名仅用于路由，不改写连接目标。
- **Mux**：连接复用，可降低延迟，但可能导致断流，请谨慎使用。可分别设置 **TCP 并发**、**XUDP 并发** 与 **QUIC 流量处理方式**（多路复用 / 原生 / 不代理）。
- **Fragment**：拆分早期 TCP 流量，仅在需要时启用。可设置 **分片方式**、**分片包长** 与 **分片间隔**。

::: details 核心实现
- **FakeDNS** 对应 Xray 的 `fakeDns` 地址池；收到 DNS 查询时返回池中的虚拟 IP，连接时再还原为域名，因此路由可以按域名匹配。
- **Sniffing** 对应入站的 `sniffing`，`routeOnly` 为 `true` 时，嗅探结果只参与路由，不替换连接目标。
- **Mux** 写入节点出站的 `mux` 字段：`concurrency`、`xudpConcurrency`、`xudpProxyUDP443`。
- **Fragment** 会生成标签为 `fragment` 的 `freedom` 出站，节点通过 `sockopt.dialerProxy` 经由它发出连接。
:::

### 日志

**日志等级** 控制核心日志的详细程度；开启 **记录访问日志** 后可在 **设置 → 日志 → 访问日志** 查看每条连接的去向。

## 高级设置

- **IPv6**：启用 IPv6 支持；**IPv6 优先** 让连接优先使用 IPv6 地址。
- **广播控制**：允许外部应用通过广播控制服务，见 [自动化与外部控制](./automation#broadcast)。
