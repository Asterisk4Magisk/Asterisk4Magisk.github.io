# AsteriskMETA

AsteriskMETA 是基于 **Mihomo**（Clash Meta）或 **Meow** 核心的客户端，以「配置文件」为中心：导入 Clash / Mihomo YAML 订阅后，其中的代理组、规则与 Providers 会直接生效；需要调整时，可通过应用设置或 JavaScript 覆写脚本修改，而不必改动订阅本身。

底部导航共四页：**首页**、**代理**、**配置** 和 **设置**。

## 核心版本 {#core-editions}

| | Mihomo 版 | Meow 版 |
| --- | --- | --- |
| APK 文件名 | 不带 `-meow` | 带 `-meow` |
| 运行模式 | VPN Service、TPROXY、TUN、TUN2SOCKS、BPF2SOCKS | 同左，但**不支持 TUN（ROOT）** |

两版包名相同，直接覆盖安装即可切换，用户数据保留。若切换到 Meow 版时正在使用 TUN（ROOT），运行模式会自动恢复为 VPN Service，并关闭开机自启。

## 首页 {#home}

- **启动服务** / **停止服务**，以及本次运行时长、当前配置与当前节点。
- **代理模式**：**规则**（按配置规则分流）、**全局**（全部走 `GLOBAL` 组选中的节点）、**直连**。对应 Mihomo 配置的 `mode` 字段，切换时由应用写入，无需修改订阅。
- **订阅摘要**：订阅提供用量信息时，显示已用、剩余、总量与有效期。
- 四个监控卡片，点击进入详情：

| 卡片 | 内容 |
| --- | --- |
| **流量** | 今日总量、本次服务累计、5 分钟趋势、近 7 日 / 近 30 日统计。流量历史仅保存在应用私有存储中 |
| **连接** | 活动连接与已断开连接，可搜索、按速率 / 时间 / 目标排序；详情显示命中规则、策略链、来源进程；可关闭单个或全部连接 |
| **资源** | 核心进程的 CPU、内存占用与峰值 |
| **网络** | 本地 IPv4 / IPv6、默认网关、DNS 服务器，以及出口公网地址与 Cloudflare 节点位置 |

::: info 网络状态的隐私说明
进入网络状态页或刷新时，应用会向探测服务各发送一次地址查询。请求不包含订阅、配置、设备标识或账号信息；结果只保留在内存中。
:::

## 配置

### 添加配置

在 **配置** 页点击 **添加配置**：

- **URL**：添加远程订阅并立即同步；
- **文件**：导入本地 Mihomo YAML 文件；
- **二维码**：扫描 `clash://` 或 `clashmeta://` 导入二维码。

URL 配置的选项：

| 字段 | 说明 |
| --- | --- |
| **名称** | 留空则首次同步后自动命名 |
| **更新间隔（小时）** | 自动更新周期 |
| **通过代理更新** | 经由当前代理下载订阅 |
| **User-Agent** | 请求订阅时使用的 User-Agent，可自定义 |
| **HWID** | 向限制设备数量的服务商上报设备标识；被拒绝或超限时会提示 |
| **Age 私钥** | 用于解密 Age 加密的订阅 |

保存时应用会依次执行下载、解密、校验。任一阶段失败时，可以 **重试**、**仍然保存**（保留暂时不可用的配置）或取消继续编辑。

### 管理配置

每个配置的菜单提供 **同步**、**预览**（查看最终生效的 YAML）、编辑与删除；页面菜单中的 **更新所有订阅** 会依次更新全部远程配置。

- **同步子订阅**：更新配置中的远程 `proxy-providers`。
- **子订阅用量**：配置包含 Provider 时，可展开查看各 Provider 的用量与到期时间（需要代理运行中）。

修改运行中的配置后，应用会提示 **更改尚未生效**，点击 **立即应用** 即可让运行中的服务使用新配置。

### 覆写脚本与原始配置

编辑配置时可以选择一个 **覆写脚本**，或开启 **完全关闭覆写**：

- **覆写脚本**：在服务启动前用 JavaScript 转换配置内容。
- **完全关闭覆写**（**原始配置**）：仅原样加载 YAML，应用设置与覆写脚本都不生效。此时设置页中相应项目会显示为只读的 **来自 YAML**。端口等必要字段缺失时可能无法启动，应用会给出 **配置检查** 结果。

哪些字段由应用托管、脚本接口与示例、原始配置的具体要求，见 [Mihomo 配置](./core-mihomo)。

## 覆写脚本

**设置 → 高级设置 → 覆写脚本** 管理全部脚本，可新建、编辑、复制与删除。编辑器支持 **格式化 JavaScript**。

点击 **调试**，选择一个 **临时测试配置** 运行脚本，可以看到：

- **输出 YAML**：脚本处理后的完整配置；
- **Console**：脚本中 `console` 的输出；
- **摘要**：处理前后的节点、策略组、规则数量变化。

调试结果可 **复制报告**，便于排查。脚本需要定义同步函数 `main(config)`，接口说明与示例见 [Mihomo 配置 · 覆写脚本](./core-mihomo#script)。

## 代理

**代理** 页显示配置中的策略组，点击节点即可切换（仅手动选择类策略组可切换）。

- **整组测试**：对策略组内全部节点测速。
- **定位当前选中节点**、**搜索代理**。
- **代理显示选项**：代理组布局（**展开列表** / **顶栏标签页**）、代理布局（自动 / 单列 / 双列 / 多列）、排序（默认 / 延迟 / 名称），以及切换节点时 **中断连接**。
- 右上角进入 **Providers**，分别查看 **Proxy Providers** 与 **Rule Providers**，可刷新单个或全部、预览规则集内容。

::: details 核心实现
策略组来自配置的 `proxy-groups`。常见类型：`select`（手动选择，可在本页切换）、`url-test`（自动选最低延迟）、`fallback`（按顺序选第一个可用）、`load-balance`（负载均衡）。自动类型的组由核心按组内的 `url` 与 `interval` 定期测速并自行决定当前节点，因此在本页无法手动切换。

**整组测试** 使用组内配置的测试地址；组未指定时使用 **连接测试** 中的测试链接。开启 **统一延迟**（`unified-delay`）后，核心会在已建立的连接上再测一次，去掉握手耗时，使不同协议的延迟更可比。
:::

## 设置

### 常规

| 设置项 | 说明 |
| --- | --- |
| **资源管理** | 见 [通用功能 · 资源管理](./common#resources) |
| **DNS 设置** | 开启 **覆写 DNS** 后，用应用中的设置替换配置的 `dns` 块：增强模式、Fake IP 地址池与过滤、默认域名服务器、域名服务器、Fallback 与 Fallback Filter、Nameserver Policy、节点域名服务器、优先 HTTP/3、遵循规则、hosts 等 |
| **域名嗅探** | 识别 HTTP / TLS / QUIC 目标域名；可设置各协议端口、是否覆写目标地址、强制 / 跳过嗅探的域名与地址 |
| **Geodata 模式** / **Geodata 加载器** | 使用 geodata 文件处理 GeoIP 规则；`memconservative` 更省内存但加载较慢 |
| **分应用代理** | 见 [通用功能 · 分应用代理](./common#per-app-proxy) |
| **连接测试** | 测试链接（策略组未指定时使用）、测试超时、测试并发、**统一延迟** |
| **自动切换** | 见下文 |
| **日志等级** | 核心日志详细程度 |

::: details 核心实现：DNS 增强模式
Mihomo `dns.enhanced-mode` 有两种取值：

- `fake-ip`：为域名返回 **Fake IP 地址池** 中的虚拟地址，连接时核心再还原为域名，因此规则可以按域名匹配，且解析无需等待真实结果。**Fake IP 过滤** 中的域名会返回真实地址，适合局域网设备、NTP、游戏联机等需要真实 IP 的场景。
- `redir-host`：返回真实解析结果，兼容性更好，但按域名分流依赖嗅探。

**覆写 DNS** 关闭且配置自带启用的 `dns` 块时，以配置为准，见 [Mihomo 配置 · DNS 合并规则](./core-mihomo#dns)。
:::

## 自动切换 {#auto-switch}

**设置 → 常规 → 自动切换** 让核心在代理服务运行期间定期检测所选策略组的当前节点，失败时自动换到可用节点。应用本身无需常驻后台。

| 设置项 | 说明 |
| --- | --- |
| **开启自动切换** | 总开关 |
| **监测的策略组** | 至少选择一个**手动选择组**；只监测直接选中的节点。切换配置后需重新选择 |
| **偏好地区** / **自定义偏好节点名称关键词** | 优先换到这些地区的节点；地区根据节点名称中的国旗、地区名与缩写识别 |
| **连续失败触发次数** | 默认 1 次，可设 1–10 |
| **检测间隔** | 默认 30 秒，可设 10–3600 秒 |
| **期望延迟** | 默认 300 ms；找到第一个低于该值的可用节点就切换。设为 0 表示检测全部节点后选最快的 |
| **恢复切回** | 原节点连续 3 次检测成功后切回 |

检测使用 **连接测试** 中的测试地址、超时与并发设置。当前节点正常或已被手动更改时不会切换；候选节点全部不可用时保留原选择。**切换日志** 可查看下次检测时间、各策略组状态与最近事件。

::: warning
- 自动切换需要内置核心，上传的自定义核心不支持此功能。
- 使用原始配置时，核心遵循 YAML 中的 `asterisk-auto-switch` 字段，应用内的设置会保存但不生效。字段格式见 [Mihomo 配置 · asterisk-auto-switch](./core-mihomo#auto-switch-field)。
:::
